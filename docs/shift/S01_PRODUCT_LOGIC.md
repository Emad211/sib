## ۱. قواعد سراسری

| شناسه | قاعده | تست پذیرش (نمونه) |
|---|---|---|
| R-01 | کارمند هیچ داده‌ای از شیفت‌های قبل نمی‌بیند، حتی شیفت‌های خودش | پس از بستن شیفت، API هیچ رکوردی از آن برای همان کاربر برنمی‌گرداند |
| R-02 | عدد مرجع قفسه و صندوق هرگز نمایش داده نمی‌شود (ADR-011) | جست‌وجوی عدد مرجع در همهٔ پاسخ‌های API در سناریوی کامل ← صفر |
| R-03 | هیچ ثبتی پاک یا ویرایش نمی‌شود؛ اصلاح = ثبت تازه با ارجاع (ADR-010) | UPDATE یا DELETE روی جدول رویداد ← خطای دیتابیس |
| R-04 | هر ثبت: فرد، زمان، شیفت | ستون‌های اجباری |
| R-05 | حسابداری فقط خوانده می‌شود | اتصال پل `mode=ro`؛ تست نوشتن ← خطا |
| R-06 | روی شبکهٔ داخلی، بدون اینترنت | اجرای کامل با کارت شبکهٔ قطع از اینترنت |
| R-07 | هر کس فقط کار شیفت فعلی خودش را می‌بیند | ماتریس دسترسی |
| R-08 | یک نفر می‌تواند چند نقش داشته باشد | کاربر پرستار + انباردار |
| R-09 | تغییر تنظیمات از شیفت بعد اعمال می‌شود | تغییر در میانهٔ شیفت ← شیفت جاری بی‌تغییر |
| R-10 | هر صفحه یک کار؛ متن کوتاه، عدد بزرگ، آیکون | بازبینی UX با کاربر واقعی |

## ۲. تحویل شیفت

| شناسه | قاعده |
|---|---|
| H-01 | فرمول قفسه: `E = C0 + R − D − U − W` (معانی در سند منبع) |
| H-02 | فرمول صندوق: `N = N0 + P_cash − B − W` |
| H-03 | تحویل با صورت‌حساب باز شروع نمی‌شود (خواندن فاکتورهای باز از حسابداری) |
| H-04 | ترتیب در هر جریان: شمارش (صندوق کور دونفره؛ قفسه‌ها فقط ورودی) ← چک‌لیست ← بسته‌های بار در راه ← امضای دو طرف؛ هر جریان امضا و پایان خودش را دارد (H-12) |
| H-05 | عدم تطابق قلم: دوباره بشمار ← خروجی کور بشمارد؛ اگر شمارش سوم با مرجع بخواند «تطابق»، بدون شمارش مشترک و بدون مغایرت (Q-09، ADR-017) ← وگرنه هر دو با هم ← عدد مشترک = مرجع بعدی؛ مغایرت به نام خروجی |
| H-06 | کسری فقط هشدار است، بدون کسر از حقوق |
| H-07 | اقلام غیرشیفتی (انبار اصلی): مغایرت بدون نام مقصر *(پیش‌فرض)* |
| H-08 | خروج زودهنگام نفر خروجی: شروع اضطراری تک‌نفره نفر ورودی پس از تأیید تلفنی مدیر؛ تأیید به‌صورت رویداد ثبت می‌شود (چه کسی، چه زمانی). مغایرت این مسیر بی‌نام می‌ماند و برای بررسی به مدیر می‌رود؛ هرگز خودکار به نام نفر غایب نوشته نمی‌شود (ADR-017) |
| H-09 | بلوک: تحویل به خود انجام نمی‌شود؛ فقط ابتدا و انتهای بلوک؛ محرمانگی حتی در بلوک |
| H-10 | فقط یک مسئول صندوق و قفسهٔ پذیرش در هر شیفت؛ نفر دوم فقط رویداد ثبت می‌کند |
| H-11 | برش زمانی: هر چه در حسابداری پس از شروع تحویل ثبت شود، مال شیفت بعد است (تفسیر فنی قاعدهٔ «بیمار کاغذی»، S02) |
| H-12 | دو جریان مستقل تحویل: پذیرش (صندوق + قفسهٔ پذیرش) و پرستاری (اتاق CPR + ترالی). هر جریان session و `handover_id` جدا دارد و هیچ‌کدام منتظر دیگری نمی‌ماند (ADR-017) |
| H-13 | مغایرت صندوق بین ورودی و خروجی: یک بازشماری مشترک توسط هر دو نفر ← عدد توافق‌شده ثبت می‌شود ← اختلاف آن با مرجع به‌عنوان مغایرت ثبت می‌شود (ADR-017) |

## ۳. رویدادها

کدها: ک (کارت‌به‌کارت)، ب (برگشت/ابطال)، ت (تخفیف کمپین)، د (برداشت از صندوق، سقف ۳۰۰٬۰۰۰ تومان)، ا (اختلاف، خودکار)، ض (ضایعات، تأییدکننده ≠ مقصر)، و (ورودی وسط شیفت)، م (امانت بیمار، بیرون از شمارش). همچنین: برداشت اضطراری انبار (دونفره، پاکت پلمب)، خرابی تجهیزات (ارجاع با مهلت)، قند و فشار (پیشنهاد مسیر پیگیری بالای آستانه)، و چک‌لیست خدمه.
جزئیات هر کد در جدول سند منبع است. ماشین حالت هر کدام در S03.

## ۴. خرید و انبار

زنجیره: انباردار ← مدیر ← مسئول خرید ← پذیرش (دریافت با عکس فاکتور، شمارش تک‌واحد، بدون قیمت) ← دست‌به‌دست شیفت‌ها ← انباردار ← حسابدار (قیمت و پرداخت). بار مشکل‌دار پرداخت را قفل می‌کند. مرجوعی به فاکتور اصلی وصل است. شمارش هفتگی انبار از شنبه تا دوشنبه انجام می‌شود و در صورت انجام نشدن هشدار می‌دهد. هر کد کالا فقط در یک محل است *(پیش‌فرض)*.

## ۵. پاداش

قند و فشار (خودکار)، مسیر پیگیری، ثبت بیمار (چک کد ملی، رد موبایل تکراری، نمونهٔ تماس)، و کار ارجاعی مدیر. پاداش به ماه تأیید تعلق دارد و ابطال از فیش ماه بعد کم می‌شود *(پیش‌فرض)*. هر کس فقط رتبهٔ خودش و هدف تیمی را می‌بیند.

## ۶. مدیر

کارت روزانه ساعت ۷:۳۰ (جمعه ندارد؛ کارت شنبه دو روز را پوشش می‌دهد) با ۷ بخش، و تنظیمات اقلام، نقش‌ها، سقف‌ها، کمپین‌ها و پاداش.

## ۷. موارد باز در سند منبع

- مسئول خرید کیست؟
- ستون «حداقل» و «کد کالا» ۶۹ قلم خالی است. بدون کد کالا، شمارش کور قفسه کار نمی‌کند.
- واحدهای اتاق CPR باید چک شوند.
- ۵ پیش‌فرض (تصمیم‌های ۲۷ تا ۳۱) هنوز قابل تغییرند.

# O05 — دسترسی آنلاین رئیس و مدیر به اپ شیفت

این سند راه‌اندازی دسترسی بیرون از درمانگاه را برای دو نفر (رئیس با آیفون، مدیر با اندروید) می‌گوید.
اصل‌ها:

- **داده و کلید روی رایانهٔ درمانگاه می‌ماند.** رله فقط بسته‌های TLS را بر اساس نام (SNI) جابه‌جا می‌کند؛ گواهی، کلید و هیچ داده‌ای روی آن نیست.
- **درمانگاه به اینترنت وابسته نمی‌شود.** گوشی‌های داخل درمانگاه همان نشانی LAN و CA داخلی را نگه می‌دارند؛ فقط گوشی رئیس و مدیر روی نام عمومی جفت می‌شوند.
- **هیچ پورتی روی اینترنت درمانگاه باز نمی‌شود.** رایانهٔ درمانگاه خودش تونل را رو به بیرون باز می‌کند.

```
گوشی رئیس/مدیر ──HTTPS:443──▶ رله (HAProxy، عبور SNI) ──تونل Rathole (noise)──▶ رایانهٔ درمانگاه:8443 (serve_lan، گواهی Let's Encrypt)
گوشی‌های داخل درمانگاه ──HTTPS──▶ رایانهٔ درمانگاه:8443 (همان پورت، گواهی CA داخلی)
```

## ۱. آنچه لازم است (تصمیم و خرید با مالک)

| چیز | توضیح |
|---|---|
| VPS ایران | یک هسته، ۱ گیگ رم، IPv4 عمومی، اوبونتو ۲۲ یا ۲۴. پیشنهاد پژوهش: آسیاتک (اصلی)، افرانت (پشتیبان). **پیش از قرارداد سالانه، آزمون ۲۴ ساعته (بخش ۵).** |
| نام عمومی | زیردامنه روی دامنهٔ درمانگاه، رکورد A خاکستری (DNS-only) در Cloudflare به IP رله، TTL یک روز |
| توکن Cloudflare | فقط «Zone:DNS:Edit» برای همان zone؛ روی رایانهٔ درمانگاه در `<DataDir>\secrets\cloudflare-token.txt` |
| ابزارها | `rathole.exe`، `lego.exe`، `nssm.exe` در `<ToolsDir>` روی رایانهٔ درمانگاه؛ `rathole` لینوکسی روی VPS. اسکریپت‌ها چیزی دانلود نمی‌کنند. |

## ۲. رله (یک بار)

```bash
sudo PUBLIC_NAME=shift.clinic.example RATHOLE_BIN=/root/rathole bash apps/shift/deploy/online/relay-setup.sh
```

HAProxy فقط نام عمومی را به `127.0.0.1:7443` رله می‌فرستد (`haproxy.cfg`) و هر نام دیگر یا اتصال بدون SNI را رد می‌کند. توکن و کلید عمومی تونل در `/root/clinic-tunnel-secrets.txt` نوشته می‌شود؛ به رایانهٔ درمانگاه منتقل و سپس پاک شود.

## ۳. رایانهٔ درمانگاه

1. **تونل:** `./tunnel-install.ps1 -DataDir C:/ShiftData -ToolsDir C:/ShiftTools -Relay <IP رله> -Token <token> -ServerPublicKey <key>` — سرویس `ShiftTunnel`.
2. **گواهی:** `./cert-issue.ps1 -DataDir C:/ShiftData -ToolsDir C:/ShiftTools -Domain shift.clinic.example -Email <ایمیل مالک> -RegisterTask` — گواهی در `C:/ShiftData/tls/public/`؛ تمدید هفتگی خودکار.
3. **اپ:** serve_lan را با نام عمومی اجرا کنید:

```powershell
python deploy/serve_lan.py --home C:/ShiftData --ip <IP شبکه> --public-name shift.clinic.example `
  --public-cert C:/ShiftData/tls/public/fullchain.pem --public-key C:/ShiftData/tls/public/privkey.pem
```

   و `SHIFT_PUBLIC_ORIGIN=https://shift.clinic.example` را در محیط سرویس بگذارید تا QR «بیرون از درمانگاه» درست ساخته شود.
   اگر به‌جای serve_lan از Caddy استفاده می‌شود (ADR-015)، در `Caddyfile` یک بلوک `https://shift.clinic.example { tls C:/ShiftData/tls/public/fullchain.pem C:/ShiftData/tls/public/privkey.pem  reverse_proxy 127.0.0.1:8443 }` بیفزایید و `local_addr` تونل را پورت HTTPS کدی بگذارید.

## ۴. جفت کردن گوشی رئیس و مدیر

صفحهٔ «گوشی‌ها» → کارمند → تیک «گوشی بیرون از درمانگاه هم کار می‌کند» → QR. نشانی QR با نام عمومی است؛ گوشی گواهی Let's Encrypt را بدون نصب CA قبول می‌کند. آیفون رئیس اپ را به‌صورت PWA از Safari («افزودن به صفحهٔ اصلی») دارد؛ APK فقط اندروید است.
پس از جفت شدن، ورود دومرحله‌ای (کد شش‌رقمی برنامهٔ Authenticator) برای مدیر روشن می‌شود (بخش ۶).

## ۵. آزمون ۲۴ ساعتهٔ رله (پیش از خرید سالانه)

1. دو یا سه ارائه‌دهنده را ساعتی اجاره کنید (هزینه با مالک).
2. روی هر کدام بخش ۲ را اجرا کنید و `relay-check.sh` را از گوشی با هر سیم‌کارت در چهار زمان (صبح، ظهر، عصر، شب) بزنید:

```bash
bash relay-check.sh https://shift.clinic.example 20
```

3. نتیجه را در جدول زیر بنویسید؛ ملاک: کد ۲۰۰ در دست‌کم ۹۵٪ تلاش‌ها و میانهٔ `total_s` زیر ۱ ثانیه.

| ارائه‌دهنده | اپراتور | زمان | موفق / کل | میانهٔ اتصال (s) | میانهٔ TLS (s) | میانهٔ کل (s) | یادداشت |
|---|---|---|---|---|---|---|---|
| | همراه اول | صبح | | | | | |
| | ایرانسل | صبح | | | | | |
| | رایتل | صبح | | | | | |

## ۶. امنیت

- ورود دومرحله‌ای برای نقش مدیر، اتصال نشست به دستگاه و محدودیت تلاش ورود در خود اپ است (ADR-026، ADR-027).
- HSTS فقط پس از پایدار شدن گواهی عمومی روشن شود.
- **ریسک DNS:** در قطع اینترنت بین‌الملل، نام Cloudflare ممکن است حل نشود؛ TTL یک روز و در صورت نیاز یک دامنهٔ پشتیبان با DNS داخلی (آروان) — تصمیم با مالک.

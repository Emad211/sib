# امنیت و حریم خصوصی

> نسخه 1.0 · ۱۴۰۵/۰۸/۰۴ · مبنا: ADR-006

## ۱. داده‌ها و طبقه‌بندی

| طبقه | نمونه | قاعده |
|---|---|---|
| **PHI** | نام، کد ملی، موبایل، خدمات و داروی هر بیمار | فقط روی دستگاه‌های درمانگاه و دستگاه توسعه در `_data/`؛ هرگز در گیت، CI، چت، سرویس ابری، ایمیل یا اسکرین‌شات اشتراکی |
| **مالی** | قیمت‌ها، درآمد، حقوق | مثل PHI |
| **عملیاتی** | شمارش‌ها، عدد مرجع | عدد مرجع فقط برای مدیر (ADR-011) |
| **آمار تجمیعی** | درصدها، میانگین‌ها، شمارش کل | مجاز در اسناد و ساخت دیتابیس مصنوعی |

## ۲. قواعد کار با کپی پروداکشن

1. کپی فقط از روی پشتیبان یا با backup API گرفته می‌شود، نه از فایل در حال استفاده.
2. محل: `sib/_data/prod_snapshot/<name>_<date>.db`. پوشهٔ `_data/` در `.gitignore` است.
3. باز کردن فقط با `mode=ro`. تست‌هایی که می‌نویسند روی **کپیِ کپی** در پوشهٔ موقت اجرا می‌شوند.
4. هیچ ردیف واقعی در فایل‌های تست، اسناد، issueها یا پیام‌ها کپی نمی‌شود. برای مثال، داده ساخته می‌شود.
5. کپی‌های قدیمی‌تر از ۹۰ روز پاک می‌شوند، مگر برای گولدن مستر لازم باشند.
6. روی دستگاه توسعه، رمزگذاری دیسک (BitLocker) روشن باشد (Q-13).

## ۳. تهدیدها و کنترل‌ها

| تهدید | کنترل |
|---|---|
| جعل نشست با کلید ثابت | SEC-01 ← کلید یکتا برای هر نصب |
| دسترسی از دستگاه ناشناس در Wi-Fi درمانگاه | Wi-Fi کارکنان جدا از Wi-Fi مهمان (Q-14)؛ ورود اجباری؛ نشست محدود |
| کارمند کنجکاو در گزارش‌ها | ماتریس دسترسی؛ لاگ فعالیت برای خواندن حساس (فاز ۲) |
| از دست رفتن دیتابیس | O01 |
| commit تصادفی داده | `.gitignore` + پاک کردن `.db` از گیت (ACC-0.3) + اسکن secret و `.db` در CI |
| نشت عدد مرجع در اپ شیفت | ADR-011 + تست |
| بدافزار روی رایانهٔ پذیرش | خارج از کنترل کد؛ پشتیبان خارج از آن رایانه (O01) |

## ۴. ثبت حادثهٔ امنیتی

هر گمان نشت داده یا دسترسی غیرمجاز طبق O02 و همان روز به مالک گزارش می‌شود.

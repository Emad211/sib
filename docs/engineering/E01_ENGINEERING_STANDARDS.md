# استانداردهای مهندسی

> نسخه 1.0 · ۱۴۰۵/۰۸/۰۴

## ۱. گیت

- شاخهٔ اصلی `main` همیشه قابل انتشار است. کار روی شاخهٔ `feat/<id>-<slug>`، `fix/<id>-<slug>` یا `docs/<slug>`.
- PR کوچک: یک کار نقشهٔ راه، و ترجیحاً کمتر از ۴۰۰ خط تغییر کد (بدون تست).
- عنوان PR: `ACC-1.2: daily backups via SQLite backup API`.
- commit انگلیسی، با فعل امری: `fix: validate backup file names (SEC-02)`.
- ادغام فقط با CI سبز. squash merge.
- ریپوی قدیمی: بدون اجازهٔ صریح مالک هیچ عملیات نوشتنی انجام نمی‌شود (CLAUDE.md، قاعدهٔ ۴).

## ۲. پایتون

- پایتون 3.13، و type hint برای هر کد جدید.
- `ruff` (lint + format) و `mypy --strict` روی `domain/` و `services/`؛ روی بقیه تدریجی.
- بدون `except Exception: pass`. هر except یا مشخص است یا لاگ می‌کند و دوباره پرتاب می‌کند.
- SQL فقط در `adapters/`، فقط پارامتری. نام جدول یا ستون پویا فقط از فهرست سفید.
- پول عدد صحیح است. زمان فقط از `domain/shifts.py` و `config`.
- رشته‌های فارسی رابط کاربری در template یا یک فایل پیام، نه پراکنده در منطق.

## ۳. تست

- A04 مرجع است. هر باگ = تست رگرسیون قرمز، بعد رفع.
- نام تست: `test_<what>_<condition>_<expected>`.
- fixtureهای دیتابیس فقط مصنوعی‌اند. تست‌هایی که کپی پروداکشن می‌خواهند با `@pytest.mark.prod_snapshot` علامت می‌خورند و در CI رد می‌شوند.

## ۴. بازبینی

چک‌لیست بازبینی هر PR:

1. به کار نقشهٔ راه وصل است؟
2. رفتار کاربر عوض شده؟ CHANGELOG دارد؟
3. schema عوض شده؟ مهاجرت افزایشی است و تست‌های A03 را دارد؟
4. پول، زمان یا دسترسی را لمس کرده؟ تست ویژگی یا ماتریس دارد؟
5. دادهٔ واقعی یا کلید در diff نیست؟
6. سند مرتبط به‌روز شده؟

## ۵. تعریف «انجام شد»

کد ادغام شده · CI سبز · پوشش پایین نیامده · سندها به‌روز · برای تغییرهای مالی یا گزارشی، گولدن مستر محلی بی‌اختلاف · برای تغییرهای قابل‌دید، تأیید مالک.
